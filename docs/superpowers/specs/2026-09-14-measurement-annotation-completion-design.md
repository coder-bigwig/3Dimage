# Measurement and Annotation Completion Design

## Goal

收尾现有医学 3D 查看器的测量与标注能力，形成可验证、可保存、可恢复的本地查看器工具闭环；“发送”按钮继续保留但禁用。

## Scope

### Measurement tools

- 支持长度、直径、角度和闭合面积四种测量。
- 测量点必须通过模型拾取获得，并保存为模型局部坐标，因此旋转视角不会破坏测量。
- 支持新建、撤销、清空和关闭；测量数据只属于当前查看器会话，不进入标注服务端文档。
- 继续使用现有的单位和格式化方式：长度/直径为 `mm`，角度为度数，面积为 `mm²`。

### Annotation tools

- 二维标注支持画笔、直线、箭头、圆、矩形、文字、颜色选择、撤销、清空和关闭。
- 三维标注支持在模型表面添加文字、编辑、删除、撤销、清空和长按拖动标签；标签锚点保持在模型局部坐标。
- 标注文档通过现有共享查看器 API 自动加载和保存，使用版本号处理并发冲突。
- 加载失败时禁止在未知服务端文档上继续编辑；保存失败时保留本地改动并提供重试/重新加载路径。
- “发送”按钮不发请求，继续保持禁用，并通过测试固定这一约束。

### Cleanup and delivery

- 删除本次验证产生的 `artifacts/` 临时文件；不删除源代码、测试结果所需的固定资源或用户已有文件。
- 运行前端类型检查、单元测试、构建和 lint。
- 运行后端测试，并在可用的 Compose/API/PostgreSQL 环境中运行测量与标注端到端测试。
- 验证通过后，将本次功能代码、测试、迁移和文档整理为提交；不提交无关工作区改动。

## Architecture

测量记录由 `ToolRecords` 管理，`InteractiveTools` 负责模型射线拾取、模型局部坐标锚点、可视化和标签投影。测量只保留在查看器工具状态中。二维标注由 SVG 绘制层管理，三维标注复用模型局部锚点和投影标签能力。

标注持久化沿用现有的共享查看器标注文档：前端通过 GET/PUT 读取和写入版本化文档，后端在 PostgreSQL 中对版本执行原子比较并更新。前端串行化保存请求，并在保存返回期间保留用户继续做出的修改；HTTP 409 只触发显式冲突处理，不覆盖服务器的新版本。

## Error handling

- 无效或不可见模型拾取显示可理解的提示，不创建半成品记录。
- 角度、面积和标注文本不足以完成操作时保留 pending 状态，撤销优先撤销 pending 点。
- 2D/3D 标注超出数量、坐标、文本或文档大小限制时拒绝保存并保留本地状态。
- 服务端加载、保存或版本冲突时显示状态，用户可以重试或确认丢弃本地改动后重新加载。
- 所有可交互入口保持键盘可达；发送按钮明确 disabled，避免产生未定义网络行为。

## Acceptance criteria

1. 四种测量均能从真实模型表面拾取点并显示正确格式的结果；撤销、清空和关闭行为有测试覆盖。
2. 二维标注的六种绘制/文字工具能够生成、撤销、清空并在刷新后恢复。
3. 三维标注能够添加、编辑、删除、撤销、拖动标签且刷新后保持模型锚点和文本。
4. 标注 API 的权限、非法数据、过期共享链接和版本冲突测试通过。
5. 前端 typecheck、unit tests、lint、build 通过；后端测试和真实 API 端到端流程通过。
6. “发送”保持禁用，且不会产生网络请求。
7. 工作区无本次验证产生的临时 `artifacts/` 文件，提交内容边界清晰。

## Out of scope

- 实现发送、分享给其他用户、通知或导出标注。
- 改变现有共享查看器权限模型。
- 重新设计查看器视觉布局或更换测量算法。
