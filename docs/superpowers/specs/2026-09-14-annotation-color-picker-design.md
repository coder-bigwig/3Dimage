# 二维标注自定义取色器设计

## 目标

将二维标注工具中的“调色”从固定色块/浏览器原生颜色输入，升级为接近参考界面的自定义取色器。用户可以通过色谱、色相条、RGB 数值或 HEX 输入选择颜色，并在确认后将其用于后续新建的二维标注。

本次不修改模型分层颜色，也不修改三维标注的现有黄色文字样式。

## 用户交互

1. 点击“调色”或自定义颜色色块，打开取色面板。
2. 面板打开时复制当前工具颜色，作为“当前”颜色与可编辑的颜色草稿。
3. 用户可通过以下任一方式编辑草稿：
   - 二维色谱：横向选择饱和度，纵向选择明度；
   - 垂直色相条：选择色相；
   - RGB 输入框：分别输入 0–255 的红、绿、蓝值；
   - HEX 输入框：输入 `#RRGGBB` 或不带 `#` 的六位值。
4. “新增”预览显示草稿颜色，“当前”预览显示打开面板前的颜色。
5. 点击“确定”后提交规范化的六位小写 HEX 颜色并关闭面板。
6. 点击“取消”、按 `Esc` 或关闭面板时放弃草稿，不触发颜色提交。
7. 非法 HEX 不允许提交，并给出明确的输入错误；RGB 值限制在 0–255。
8. 固定快捷色块继续保留，点击后立即切换工具颜色，不影响已存在的标注。

## 组件与数据流

新增独立的 `ColorPicker` 组件负责面板状态、取色交互、输入校验和可访问性。新增纯函数负责 HEX、RGB、HSV 之间的转换，以便单元测试。

颜色数据流为：

```text
快捷色块 / ColorPicker 确定
        ↓
AnnotationToolbar.onColor
        ↓
ViewerShell.color
        ↓
新建二维 Drawing.color
```

取色器内部使用草稿状态，不直接修改 `ViewerShell.color`。`DrawingCanvas` 创建新图形时读取当时的 `color`，因此已有二维标注保持原色。三维标注路径不接入本次取色器。

## 实现边界

- 修改 `AnnotationToolbar`，把调色按钮和自定义色块接入取色面板。
- 新增颜色转换工具和 `ColorPicker` 组件。
- 在现有标注样式中增加面板、色谱、色相条、输入框、预览和窄屏布局样式。
- 不新增第三方依赖。
- 不改变后端标注文档格式；二维标注继续保存其自身的 `color` 字段。

## 可访问性与响应式

- 面板使用 dialog 语义，并为色谱和色相条提供 slider 语义、当前值和键盘调整能力。
- RGB 与 HEX 输入具有可读标签；错误状态通过文本和 `aria-invalid` 暴露。
- 确定、取消按钮可通过键盘操作；`Esc` 执行取消。
- 桌面端保持参考界面的紧凑面板；窄屏端使用视口宽度内的面板，避免横向溢出。

## 错误处理

- HEX 输入不是六位有效十六进制值时，不更新已确认颜色，保留错误提示。
- RGB 输入在提交或失焦时规整到 0–255；空值或非数字恢复为最近一次有效值。
- 颜色转换函数对不合法输入返回明确的无效结果，不向渲染或标注层传递非法颜色。

## 测试计划

先写失败测试，再实现：

- 颜色转换函数：HEX ↔ RGB ↔ HSV 的往返转换和边界值。
- 打开取色器时显示当前颜色；编辑 RGB 后同步 HEX 和预览。
- 编辑有效 HEX 后同步 RGB 和预览；非法 HEX 阻止确认。
- 取消或 `Esc` 不调用 `onColor`；确认只提交一次规范化颜色。
- 快捷色块仍立即调用 `onColor`。
- 二维标注工具接收确认后的颜色，既有标注不因切换工具颜色而改变。
